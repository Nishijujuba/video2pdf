# Materialize target-only Acceptance Report v2 and close bounded repair

## Context

Delivery Quality Slices 7-9 provide the canonical rule contracts, three precompile semantic-owner reports, current precompile evidence, final artifact sealing, and rendered-text reconciliation. The final decision still needs one provider-owned aggregation boundary that preserves those precompile decisions and adds an independent Visual Quality Judgment Patch, exact page coverage, crash recovery, and a finite semantic repair route.

## Decision

Implement a deep `AcceptanceV2Provider` behind the public `acceptance-*` commands. `acceptance-prepare` binds one immutable target-only input graph, the registered `workflow/run.json` bytes and current Control Store authority, the actual current `source_ready` checkpoint, and a versioned `final_quality_ready` authority projection. That projection is anchored to the current Run Record SHA and exactly enumerates the final artifacts, all eight registered Slice 8-9 evidence artifacts, and every rendered page by logical ID, path, and SHA. Before preparation, the public `acceptance-final-authority-publish` command publishes that revision through a provider-owned SQLite compare-and-swap authority under the declared Control Store root; preparation rejects any uncommitted, stale, or conflicting revision. A ninth Text Equivalence Report is required when the Precompile Text Seal reuses prior semantic judgments. This target-only Control Store projection closes final-evidence lifecycle authority while Run Record v3 remains source-scoped; native Kernel checkpoint adoption remains part of Global Gate cutover. `acceptance-patch-commit` validates independent ownership, complete coverage of the three postcompile catalog rules, the exact path-and-SHA authorized read set, and exact Visual pages `1..page_count`. The Visual Skeleton is reconstructed deterministically from the binding and policy projections; its `peer_results_visible: false` setting, complete Task Envelope, and SHA are also anchored in the SQLite Reviewer Claim. `acceptance-materialize` rechecks every input fingerprint, registered provider identity, rendered-page manifest tuple, and lineage edge; carries forward the six normalized precompile rule decisions; and aggregates the Visual Patch without semantic reinterpretation.

The only report statuses are `pass`, `fail`, and `blocked_contract_gap`. Cross-Phase Findings can only add failures to preserved precompile decisions. A complete semantic failure consumes one immutable attempt; Contract Gaps and technical publication failures consume none. The third complete failure routes to `manual_repair_required`. Patch and report publications use intent-specific staging, durable intents, revision fences, and Control Store compare-and-swap. Report publication treats `acceptance_report.json`, `attempt-record.json`, and `repair-ledger.json` as one fingerprinted bundle: the intent and CAS bind all three SHAs, recovery validates their schemas and cross-links, and terminal idempotent retries revalidate the complete immutable bundle plus committed authority. Only the CAS winner publishes an immutable report path; losing concurrent intents become `ABORTED`. `acceptance-reconcile` finishes a publication only when staged bytes match the prepared intent. Exact successful retries return the committed result.

Every materialized execution retains immutable report, attempt, and repair-ledger records under its committed report identity. The attempt record binds Run revision, Acceptance revision, predecessor and current Artifact Generation, the declared changed-generation set, an explicit judgment-to-generation dependency snapshot, dependency-derived invalidated and retained judgments, required and completed reruns, failure-set fingerprint, and routing outcome. Text Equivalence is an explicit waiver over affected precompile dependencies; all remaining intersections between `changed_generation_ids` and the dependency snapshot require reruns. Each failed semantic-attempt ledger entry is completed before repair admission with the immutable report and attempt paths plus their SHAs. Root report files remain canonical projections. `acceptance-guard-eligibility` verifies the current immutable report, attempt, ledger, committed Control Store intent, current execution authority, Run binding, terminal publication state, and every historical report/attempt reference before exposing a target-only mechanical result. It always records `delivery_authority: false`. Active Legacy `delivery_guard.py`, hooks, project instructions, and platform skills remain unchanged. Issue #43 owns Global Gate activation, Legacy adoption, v1 retirement, and active Guard integration.

## Consequences

Slice 10 can prove the full final-quality and repair lifecycle through public seams without activating v2. The current input binding is a Kernel-oriented target contract; any Legacy adapter remains cutover work. The canonical workspace is fixed at `<video_root>/review/acceptance`, where provider-owned SQLite authority enforces one active execution, fenced Reviewer Claims, publication intents, and execution revisions. A repair execution invalidates all judgments affected by the changed generation, requires the same Run identity with a higher coordination revision, names the changed artifact generations, binds the predecessor generation, and records completion of fresh upstream owner reviews plus a fresh complete Visual review.
