# Issue 30 Research: Legacy and Kernel 2.0 Delivery-Quality Contract Migration

## Conclusion

Issue 30 should specify a staged implementation with four inactive build slices followed by four explicit activation events. The inactive slices are: canonical Delivery Quality contracts and conformance; precompile semantic assurance and the Precompile Text Seal; final evidence plus rendered-text reconciliation; and final-decision materialization plus repair closure. Runtime authority changes only at the Global Gate Cutover, Bilibili Platform Kernel Cutover, YouTube Platform Kernel Cutover, and later Batch Cutover. This preserves one authority per scope and prevents unfinished Kernel components from entering Legacy runs. [`docs/adr/0050-separate-target-design-acceptance-from-runtime-activation.md:14-20`](../adr/0050-separate-target-design-acceptance-from-runtime-activation.md#L14-L20) [`docs/adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md:14-36`](../adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md#L14-L36)

The public final-decision name should remain **Acceptance Report**, with v2 replacing v1 at the Global Gate Cutover. **Delivery Quality** should become the context, catalog, projection, precompile-report, seal, reconciliation, and conformance vocabulary. The existing `final-delivery-acceptance` skill and `acceptance-*` CLI family should remain the public final-gate adapter. This choice avoids a second breaking rename while ADR 0030, ADR 0051, and Issue 11 already define the v2 retirement boundary. [`docs/adr/0030-require-acceptance-report-v2-and-retire-v1.md:10-18`](../adr/0030-require-acceptance-report-v2-and-retire-v1.md#L10-L18) [`docs/adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md:14-19`](../adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md#L14-L19) [Issue 11](https://github.com/Nishijujuba/video2pdf/issues/11)

Batch needs a new **Batch Record / Batch Item Projection** schema because that contract owns batch identity, deterministic selection order, run mapping, and read-only projections. Batch child execution should reuse the single-video Kernel Run, Subagent Task Envelope, Role Projection, checkpoints, repair limits, and delivery authority; it should not introduce a second child-workflow schema. [`docs/adr/0036-make-batch-a-projection-over-independent-video-runs.md:14-28`](../adr/0036-make-batch-a-projection-over-independent-video-runs.md#L14-L28) [`docs/adr/0020-use-kernel-issued-task-envelopes-for-every-subagent.md:13-21`](../adr/0020-use-kernel-issued-task-envelopes-for-every-subagent.md#L13-L21)

## Contract migration decisions

### 1. Canonical policy and projections

One strict, versioned Delivery Quality Rule Catalog should be the normative source for blocking quality semantics. Separately versioned Role Projections should distribute immutable guidance and assign each rule to exactly one Primary Semantic Decision Owner; projections must not rewrite requirements, violations, exceptions, or blocking effect. [Issue 37 resolution](https://github.com/Nishijujuba/video2pdf/issues/37#issuecomment-5119504292)

The catalog provider should retain the Issue 37 two-level identity model: exact-byte SHA-256 for the full catalog and canonical semantic SHA-256 for each rule. Any duplicate identity, dangling reference, ownership gap, unsupported version, unknown field, or unreproducible fingerprint must fail closed. [Issue 37 resolution](https://github.com/Nishijujuba/video2pdf/issues/37#issuecomment-5119504292)

The current criteria file remains the input policy to migrate, because ADR 0030 retires the report contract while explicitly preserving Criteria v1 until a separate criteria decision. The migration should convert each criterion into canonical rule objects without changing its normative meaning, then split `credibility_disclosure_placement` into precompile content and postcompile presentation rules as Issue 31 requires. [`docs/adr/0030-require-acceptance-report-v2-and-retire-v1.md:14-18`](../adr/0030-require-acceptance-report-v2-and-retire-v1.md#L14-L18) [Issue 31 resolution](https://github.com/Nishijujuba/video2pdf/issues/31#issuecomment-5125386777)

The canonical catalog, Role Projections, language-profile registry, counterexample corpus, conformance report, and their validators should become registered Kernel contracts governed by JSON Schema Draft 2020-12 plus separately registered relational invariant checks. Structural definitions must not be duplicated in Python or prompts. [`docs/adr/0025-use-json-schema-as-the-kernel-contract-source.md:13-21`](../adr/0025-use-json-schema-as-the-kernel-contract-source.md#L13-L21)

### 2. Lifecycle partition

The precompile phase should own `no_meta_writing_content`, `core_term_first_use_readability`, `delivery_glossary_term_strategy`, `argument_chain_integrity`, `formula_information_gain`, and the content half of disclosure. The postcompile phase should own figure integrity, table layout integrity, the presentation half of disclosure, rendered-text reconciliation, and visual quality. Each rule has one decision phase; a cross-phase finding may add a failure and cannot grant a pass. [Issue 31 resolution](https://github.com/Nishijujuba/video2pdf/issues/31#issuecomment-5125386777)

Source-Faithfulness, Writing Quality, Pyramid, and Visual Quality remain independent semantic authorities. Writer, Consistency, and repair roles have guidance or mutation authority and no blocking gate authority. A role that authored, integrated, or repaired the current generation cannot decide that generation's blocking semantic result. [Issue 36 resolution](https://github.com/Nishijujuba/video2pdf/issues/36#issuecomment-5125987419)

The Reader-Facing Text Inventory must cover the complete declared text surface and bind stable item identities, source generations, locators, exact UTF-8 fingerprints, rule applicability, and coverage. Missing raster text, unsupported constructs, duplicate identities, or uncovered regions are Contract Gaps. [Issue 35 resolution](https://github.com/Nishijujuba/video2pdf/issues/35#issuecomment-5127281654)

The Precompile Text Seal is immutable. A presentation-only mutation may create a successor seal only through deterministic bijective text equivalence; a text, policy, language-profile, glossary, semantic-dependency, or unclassified mutation requires fresh independent review. [Issue 35 resolution](https://github.com/Nishijujuba/video2pdf/issues/35#issuecomment-5127281654)

Rendered-text fidelity requires the current Precompile Text Seal, Final Artifact Seal, complete Rendered Text Object Inventory, compiler-produced Text Origin Manifest, and a closed deterministic recipe registry. Raw PDF text extraction alone is insufficient evidence of origin. [Issue 40 resolution](https://github.com/Nishijujuba/video2pdf/issues/40#issuecomment-5127478488)

### 3. Public naming

The context should migrate from `Final Acceptance Context` to `Delivery Quality Context`, and `CONTEXT-MAP.md`, the context glossary path, cross-context references, domain tests, and activation map should change together. The current domain layout makes each active context glossary the sole terminology authority. [`docs/adr/0057-adopt-multi-context-domain-documentation.md:16-28`](../adr/0057-adopt-multi-context-domain-documentation.md#L16-L28) [`CONTEXT-MAP.md:1-12`](../../CONTEXT-MAP.md#L1-L12)

The final public report should remain `Acceptance Report v2` and `acceptance_report.json`. The broader domain may publish `Delivery Quality Rule Catalog`, `Precompile Quality Report`, `Precompile Text Seal`, `Rendered Text Reconciliation Report`, and `Delivery Quality Conformance Report`. This preserves the accepted report-retirement contract while giving the broader lifecycle accurate names. [`docs/adr/0030-require-acceptance-report-v2-and-retire-v1.md:14-31`](../adr/0030-require-acceptance-report-v2-and-retire-v1.md#L14-L31)

Issue 31 and Issue 33 use `Delivery Quality Report` for the sole final decision, which conflicts with ADR 0030, ADR 0051, Issue 11, and the earlier Acceptance Report v2 contract. Issue 39 must normalize those resolutions back to `Acceptance Report v2`, or publish a new superseding ADR before implementation. Silent coexistence of both public final-decision names would create an ambiguous authority boundary. [Issue 31 resolution](https://github.com/Nishijujuba/video2pdf/issues/31#issuecomment-5125386777) [Issue 33 resolution](https://github.com/Nishijujuba/video2pdf/issues/33#issuecomment-5127679653) [`docs/adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md:31-37`](../adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md#L31-L37)

The `final-delivery-acceptance` skill should retain its public name because it remains the final-gate adapter. Canonical writing guidance and precompile evaluation should be generated from catalog projections and task envelopes, instead of expanding the final-gate skill into a second workflow authority. [`docs/adr/0027-separate-semantic-prompts-from-mechanical-workflow-contracts.md:13-29`](../adr/0027-separate-semantic-prompts-from-mechanical-workflow-contracts.md#L13-L29)

The CLI should retain the planned `legacy-acceptance-adopt`, `acceptance-prepare`, and `acceptance-reconcile` family for final-gate operations. New catalog and precompile operations should use `delivery-quality-*` names and should remain unavailable to active Legacy instructions until their owning build slice and cutover policy permit them. ### 4. Batch schema decision

The active Batch implementation owns its own manifest item states, embeds the whole single-video workflow in a free-form child prompt, accepts child JSON through `part-result.schema.json`, and still uses a global `--concurrency` option. [`.agents/skills/bilibili-batch-render-pdf/references/manifest.schema.json:42-86`](../../.agents/skills/bilibili-batch-render-pdf/references/manifest.schema.json#L42-L86) [`.agents/skills/bilibili-batch-render-pdf/references/part-result.schema.json:8-42`](../../.agents/skills/bilibili-batch-render-pdf/references/part-result.schema.json#L8-L42) [`.agents/skills/bilibili-batch-render-pdf/scripts/run_batch.py:439-505`](../../.agents/skills/bilibili-batch-render-pdf/scripts/run_batch.py#L439-L505) [`.agents/skills/bilibili-batch-render-pdf/scripts/run_batch.py:1098-1107`](../../.agents/skills/bilibili-batch-render-pdf/scripts/run_batch.py#L1098-L1107)

At Batch Cutover, that manifest and part-result authority should be retired in favor of a new registered Batch Record / Batch Item Projection contract. The Batch projection references independent `run_id` values and reads phase, checkpoint, blocker, and guarded delivery outcome; it never writes per-video state or quality decisions. [`docs/adr/0036-make-batch-a-projection-over-independent-video-runs.md:14-26`](../adr/0036-make-batch-a-projection-over-independent-video-runs.md#L14-L26)

Every Batch-created video run should consume the same single-video Subagent Task Envelope, Role Projection, Delivery Quality contracts, checkpoints, repair budget, Acceptance Report v2, and Delivery Guard. No Batch-specific Writer, Reviewer, Acceptance, or child-result schema should survive the cutover. Before Batch Cutover, the active Legacy Batch prompt must be synchronized with both Legacy single-video skills whenever a Global Gate change affects child acceptance inputs or outputs. That compatibility update carries no Kernel Batch authority; it keeps the active Legacy child contract coherent until Issue 15 retires it. ## Recommended implementation slices

### Slice A — Delivery Quality contract foundation, target-only

Implement and register the canonical catalog, language profiles, authoring and evaluation Role Projections, identity/fingerprint provider, closed violation and exception validation, projection ownership validation, the target-only context-migration contract, semantic counterexample corpus, conformance adapter interface, and conformance report. Keep the active `Final Acceptance Context` route unchanged in this slice; the coordinated context rename belongs to the Global Gate Cutover. No workflow checkpoint, Legacy skill, Guard, hook, or activation status changes in this slice. [Issue 37 resolution](https://github.com/Nishijujuba/video2pdf/issues/37#issuecomment-5119504292) [Issue 38 resolution](https://github.com/Nishijujuba/video2pdf/issues/38#issuecomment-5127056324)

Exit evidence must include positive and negative schema fixtures, semantic minimum pairs per language profile, projection-identity mutation, missing-owner mutation, unregistered-violation mutation, and public-seam evidence. A target-only conformance pass is implementation evidence and has no delivery authority. [Issue 38 resolution](https://github.com/Nishijujuba/video2pdf/issues/38#issuecomment-5127056324)

### Slice B — Precompile semantic assurance and seal, target-only

Re-scope Issue 10 to integrate Source-Faithfulness, Writing Quality, Pyramid, and Consistency guidance on the same Artifact Generations; materialize complete precompile reports; create the Reader-Facing Text Inventory and Precompile Text Seal; route deterministic content repair; rerun affected gates; and prove fail–repair–pass without changing delivery authority. [Issue 10](https://github.com/Nishijujuba/video2pdf/issues/10) [Issue 31 resolution](https://github.com/Nishijujuba/video2pdf/issues/31#issuecomment-5125386777) [Issue 36 resolution](https://github.com/Nishijujuba/video2pdf/issues/36#issuecomment-5125987419)

Final Compile remains blocked until a complete current Precompile Text Seal exists. Presentation-only reuse requires a successor seal backed by deterministic equivalence; every semantic or unclassified mutation reruns affected owners. [Issue 35 resolution](https://github.com/Nishijujuba/video2pdf/issues/35#issuecomment-5127281654)

### Slice C — Final evidence and rendered-text reconciliation, target-only

Split the build portion of current Slice 8 from activation. Implement Final Artifact Seal, guarded Final Compile, final Compile Report, final PDF promotion, complete page rendering, Render Evidence Manifest, allowed-artifact manifest, Rendered Text Object Inventory, Text Origin Manifest, reconciliation recipe registry, and Rendered Text Reconciliation Report. [`docs/adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md:48-50`](../adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md#L48-L50) [Issue 40 resolution](https://github.com/Nishijujuba/video2pdf/issues/40#issuecomment-5127478488)

This slice remains `target_only`; its final evidence cannot create `accepted` or `delivered` state before the Global Gate Cutover. [`docs/adr/0050-separate-target-design-acceptance-from-runtime-activation.md:14-20`](../adr/0050-separate-target-design-acceptance-from-runtime-activation.md#L14-L20)

### Slice D — Acceptance v2 materialization and repair closure, target-only until cutover

Re-scope Issue 11 so its v2 materializer consumes current precompile reports and seals, rendered-text reconciliation, Visual Quality judgment, cross-phase findings, and current artifact fingerprints. It should preserve one `Acceptance Report v2` decision and keep Delivery Guard mechanical. [Issue 11](https://github.com/Nishijujuba/video2pdf/issues/11) [Issue 33 resolution](https://github.com/Nishijujuba/video2pdf/issues/33#issuecomment-5127679653)

Issue 12 remains the bounded repair-closure slice after Issue 11. It must route repairs by mutation boundary, invalidate all affected evidence, count only complete materialized semantic failures against the three-attempt budget, and end in an auditable blocked state after the third failure. ## Exact activation gates

### Global Gate Cutover

Activation is allowed only when one schema-valid Exit Evidence Manifest proves the complete atomic group: catalog and projections; Criteria v1 mapping; precompile reports and seal; final evidence and rendered-text reconciliation; Acceptance Report v2 schemas, skeletons, two isolated Reviewer tasks or patches as retained by the final design, materializer and validator; Legacy Acceptance Input Set; Acceptance Execution Context and publication intent; Delivery Guard; hooks; both platform skills; Legacy Batch child compatibility; `AGENTS.md` and `CLAUDE.md`; `.agents`/`.claude` mirrors; conformance suite; policy checks; and all positive, negative, stale-evidence, fault-injection, and v1-rejection tests. [`docs/adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md:14-19`](../adr/0051-activate-acceptance-v2-globally-with-a-legacy-input-set.md#L14-L19) [`docs/adr/video-workflow-kernel-2.0-decision-map.md:127-135`](../adr/video-workflow-kernel-2.0-decision-map.md#L127-L135)

The gate must prove one Run-record-free Legacy input pass and one Kernel input pass, exact rendered pages `1..page_count`, independent semantic task completion, crash recovery at every patch/report boundary, stale-evidence invalidation, current fingerprints, mirror equality, and rejection of every v1 authority path. [`docs/adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md:48-50`](../adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md#L48-L50)

### Platform Kernel Cutovers

A platform cutover is allowed only after the Global Gate is active, all shared Kernel slices and repair closure pass, the platform adapter and lifecycle surfaces pass their policy and recovery tests, and a real new run reaches fresh guarded delivery. Existing Legacy directories remain Legacy and cannot receive synthetic Run Records or switch tracks. [`docs/adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md:20-36`](../adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md#L20-L36)

YouTube activation additionally requires current Bilibili Exit Evidence and one successful guarded Bilibili Kernel delivery. Batch activation additionally requires both platform interfaces and guarded-delivered-only success, projection rebuild, interrupted creation recovery, authentication breaker, and fairness evidence. [`docs/adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md:60-66`](../adr/0049-implement-the-kernel-in-thirteen-vertical-slices.md#L60-L66)

## Fail-closed and rollback policy

Before any cutover, a missing contract, failed test, stale mirror, unsupported identity, Contract Gap, incomplete evidence set, or failed Exit Evidence Manifest leaves the current activation status unchanged. Inactive schemas and provider code cannot authorize delivery. [`docs/adr/video-workflow-kernel-2.0-decision-map.md:127-135`](../adr/video-workflow-kernel-2.0-decision-map.md#L127-L135)

After Global Gate Cutover, v1 must never regain authority through fallback, compatibility conversion, or report translation. A fault freezes new final decisions in the affected scope until v2 evidence is repaired; existing evidence remains preserved. [`docs/adr/0030-require-acceptance-report-v2-and-retire-v1.md:14-33`](../adr/0030-require-acceptance-report-v2-and-retire-v1.md#L14-L33)

After a Platform Kernel Cutover, an individual run never rolls back to Legacy, switches tracks, or receives dual writes. A platform-wide rollback requires a separate human-authorized atomic reverse cutover with its own policy check and Exit Evidence; until then, new run creation and promotion fail closed while existing attempts may only finish inside isolated staging. [`docs/adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md:20-36`](../adr/0040-cut-over-to-the-kernel-one-platform-at-a-time.md#L20-L36) [`docs/adr/0054-fail-closed-when-the-cross-run-control-store-is-unavailable.md:14-30`](../adr/0054-fail-closed-when-the-cross-run-control-store-is-unavailable.md#L14-L30)

If the Cross-Run Control Store is missing, corrupt, locked, or version-incompatible, no Run creation, claim, admission, promotion, delivery transition, recovery transfer, or cutover may commit. Restore requires an explicitly selected validated backup and full reconciliation; absent valid backup leaves the system blocked. [`docs/adr/0054-fail-closed-when-the-cross-run-control-store-is-unavailable.md:14-30`](../adr/0054-fail-closed-when-the-cross-run-control-store-is-unavailable.md#L14-L30)

An unresolved Contract Gap blocks final materialization and automated repair without consuming the semantic repair budget. Three complete failed semantic repair attempts preserve failure evidence and route to manual repair; the Guard cannot override the decision or budget. [Issue 33 resolution](https://github.com/Nishijujuba/video2pdf/issues/33#issuecomment-5127679653)
